INNER JOIN vs LEFT JOIN: predict which rows come back

Lesson 0001 · about 20 minutes · Level 1, Recall

Your win today: given two small tables and a query, you can say which rows come back and where a condition belongs.

Before you read: recall

Write your answer from memory first. The answer appears only after you have written something.

The big picture

A report needs rows from two tables, and the join type decides which rows survive. This page has three ideas, in this order.1

Idea by idea

Idea one: INNER JOIN keeps matches only

The manual defines it: For each row R1 of T1, the joined table has a row for each row in T2 that satisfies the join condition with R1. The join condition sits in the ON clause. A row with no partner is dropped, and a NULL key never equals anything, so it never has one.

Idea two: LEFT JOIN keeps every left row

The left table is the one named before the join keyword. First, an inner join is performed. Then, for each row in T1 that does not satisfy the join condition with any row in T2, a joined row is added with null values in columns of T2. A left row with several matches appears once per match. To find unmatched rows, test IS NULL on a right-table column.

Idea three: ON or WHERE

WHERE runs on the finished result, and a comparison with NULL is never true. A WHERE test on a right-table column therefore removes the unmatched rows, and the LEFT JOIN acts like an INNER JOIN. A test that should only limit which matches count goes in ON. A test on the left table goes in WHERE, since ON never removes left rows.

Putting it together
